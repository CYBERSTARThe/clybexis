Cyber Glossary

Your cybersecurity dictionary. Search hundreds of important cybersecurity terms, learn what they mean, see examples, and understand why each concept matters.

Cybersecurity

Fundamentals

The practice of protecting computers, networks, systems, and information from digital threats.

Example: Using MFA to protect an online account.

Why it matters: Digital systems store valuable information.

CIA Triad

Fundamentals

A security model based on Confidentiality, Integrity, and Availability.

Example: Protecting a file so only authorized users can access it.

Why it matters: It provides a foundation for security planning.

Confidentiality

Fundamentals

Making sure information is only accessible to authorized people.

Example: Password-protecting private files.

Why it matters: It helps prevent unauthorized disclosure.

Integrity

Fundamentals

Making sure information remains accurate and has not been improperly changed.

Example: Using hashes to detect file changes.

Why it matters: Incorrect data can cause serious problems.

Availability

Fundamentals

Making sure systems and information are accessible when authorized users need them.

Example: Keeping backup servers available during an outage.

Why it matters: Security is not useful if important systems cannot be accessed.

Threat

Fundamentals

Anything that could potentially cause harm to a system, network, or user.

Example: A malicious email campaign.

Why it matters: Identifying threats helps organizations prepare.

Vulnerability

Fundamentals

A weakness that could potentially be exploited.

Example: An outdated application with a known security flaw.

Why it matters: Attackers often search for weaknesses.

Risk

Fundamentals

The possibility that a threat could take advantage of a vulnerability and cause harm.

Example: An unpatched server may have increased security risk.

Why it matters: Security teams prioritize risks to reduce potential damage.

Asset

Fundamentals

Something valuable that needs protection.

Example: Customer information or a company server.

Why it matters: You need to know what you're protecting.

Attack Surface

Fundamentals

The collection of possible entry points an attacker could potentially target.

Example: Websites, accounts, applications, and exposed services.

Why it matters: Reducing unnecessary exposure can improve security.

IP Address

Networking

A numerical address used to identify a device or network interface on a network.

Example: 192.168.1.20 is an example of a private IPv4 address.

Why it matters: Networks use addresses to deliver traffic.

IPv4

Networking

A common version of the Internet Protocol using 32-bit addresses.

Example: 192.168.0.1.

Why it matters: IPv4 remains widely used.

IPv6

Networking

A newer Internet Protocol designed to provide a much larger address space.

Example: IPv6 addresses look like 2001:db8::1.

Why it matters: IPv6 helps support the growing number of connected devices.

DNS

Networking

The Domain Name System translates domain names into network addresses.

Example: Turning a website name into an IP address.

Why it matters: DNS makes websites easier for people to access.

Router

Networking

A device that forwards network traffic between networks.

Example: A home router connects devices to the internet.

Why it matters: Routers help move data between networks.

Switch

Networking

A networking device that connects devices within a local network.

Example: Several computers connected to one network switch.

Why it matters: Switches organize local network communication.

LAN

Networking

Local Area Network; a network covering a relatively small area.

Example: A school computer network.

Why it matters: LANs connect nearby devices.

WAN

Networking

Wide Area Network; a network covering a large geographic area.

Example: The internet can be viewed as a massive interconnected WAN.

Why it matters: WANs connect distant networks.

Port

Networking

A logical communication endpoint used by network services.

Example: HTTPS commonly uses TCP port 443.

Why it matters: Services communicate through specific ports.

Protocol

Networking

A set of rules that determines how systems communicate.

Example: HTTP is a web communication protocol.

Why it matters: Devices need shared rules to communicate.

TCP

Networking

Transmission Control Protocol, designed for reliable network communication.

Example: Many web connections use TCP.

Why it matters: TCP helps ensure data arrives reliably.

UDP

Networking

User Datagram Protocol, a connectionless protocol that can prioritize speed.

Example: Some real-time applications use UDP.

Why it matters: Different applications need different networking behaviors.

MAC Address

Networking

A hardware-level identifier associated with a network interface.

Example: A Wi-Fi adapter has a MAC address.

Why it matters: Local networks use MAC addresses for device communication.

Authentication

Authentication

The process of verifying who a user or system is.

Example: Logging in with a password and security code.

Why it matters: Systems need to verify identities.

Authorization

Authentication

Determining what an authenticated user is allowed to access or do.

Example: An employee can view files but cannot delete them.

Why it matters: Not every user should have the same permissions.

MFA

Authentication

Multi-Factor Authentication uses multiple types of verification.

Example: Password plus a code from an authenticator app.

Why it matters: It can make stolen passwords less useful to attackers.

Password Manager

Authentication

A tool designed to securely store and manage passwords.

Example: Generating a different strong password for every account.

Why it matters: It makes unique passwords easier to manage.

Biometrics

Authentication

Authentication using physical or behavioral characteristics.

Example: Fingerprint or facial recognition.

Why it matters: Biometrics can provide another authentication factor.

Least Privilege

Authentication

Giving users and systems only the access they need.

Example: A student account cannot modify school servers.

Why it matters: Limiting permissions can reduce damage from mistakes or compromised accounts.

Access Control

Authentication

Rules and mechanisms that control who can access resources.

Example: Only administrators can change security settings.

Why it matters: It prevents unauthorized access.

Encryption

Cryptography

Transforming readable information into protected data that requires a key to decrypt.

Example: HTTPS encrypts web traffic.

Why it matters: Encryption helps protect information from unauthorized viewing.

Decryption

Cryptography

Converting encrypted information back into readable information using the appropriate key.

Example: An authorized device decrypts protected data.

Why it matters: It allows authorized users to access encrypted information.

Hash

Cryptography

A fixed-length value generated from data by a hash function.

Example: SHA-256 can produce a hash for a file.

Why it matters: Hashes can help detect changes to data.

SHA-256

Cryptography

A cryptographic hash function that produces a 256-bit hash.

Example: CyberStart's Hashing Lab can demonstrate SHA-256.

Why it matters: It is widely used for integrity and other security purposes.

Symmetric Encryption

Cryptography

Encryption where the same secret key is used to encrypt and decrypt data.

Example: AES uses symmetric encryption.

Why it matters: It can efficiently protect large amounts of data.

Asymmetric Encryption

Cryptography

Encryption involving a public key and a private key.

Example: Public-key cryptography is used in many secure systems.

Why it matters: It enables secure communication and digital signatures.

Public Key

Cryptography

A cryptographic key that can generally be shared with others.

Example: A website may provide a public key as part of secure communication.

Why it matters: Public keys are part of many secure communication systems.

Private Key

Cryptography

A secret cryptographic key that should be protected by its owner.

Example: A private key may be used to create a digital signature.

Why it matters: Losing control of a private key can compromise security.

Digital Signature

Cryptography

A cryptographic mechanism used to help verify authenticity and integrity.

Example: Software can be digitally signed by its publisher.

Why it matters: It helps users verify where data came from and whether it changed.

Malware

Malware

Malicious software designed to disrupt, damage, spy on, or gain unauthorized access to systems.

Example: A malicious program pretending to be useful software.

Why it matters: Malware is a major category of cyber threat.

Virus

Malware

Malware that can attach itself to files or programs and spread when they are executed.

Example: A malicious file that spreads when opened.

Why it matters: Viruses can affect files and systems.

Worm

Malware

Malware capable of spreading between systems without requiring the same type of user action as a traditional virus.

Example: A worm spreading through vulnerable systems.

Why it matters: Worms can spread rapidly across networks.

Trojan

Malware

Malware that disguises itself as legitimate or useful software.

Example: A fake utility that secretly performs malicious actions.

Why it matters: Trusting fake software can lead to compromise.

Ransomware

Malware

Malware that blocks access to data or systems and may demand payment.

Example: An organization discovers its files are inaccessible after a ransomware incident.

Why it matters: Ransomware can seriously disrupt organizations.

Spyware

Malware

Malware designed to secretly monitor or collect information.

Example: Software secretly collecting browsing information.

Why it matters: Unauthorized data collection can threaten privacy.

Adware

Malware

Software that displays unwanted advertisements, sometimes in ways that can create security or privacy concerns.

Example: An application repeatedly displaying unexpected advertisements.

Why it matters: Unwanted software can reduce security and user control.

Rootkit

Malware

Malicious software designed to hide its presence and maintain unauthorized access.

Example: Malware attempting to hide malicious processes.

Why it matters: Hidden malware can be difficult to detect.

Phishing

Social Engineering

A scam that attempts to trick people into revealing information or taking an unsafe action.

Example: A fake login message asking you to sign in through a suspicious link.

Why it matters: People are often targeted instead of technical systems.

Spear Phishing

Social Engineering

A targeted phishing attempt aimed at a particular person or organization.

Example: A message specifically designed for one employee.

Why it matters: Personalized scams can appear more convincing.

Smishing

Social Engineering

Phishing conducted through text messages or SMS.

Example: A fake delivery text containing a suspicious link.

Why it matters: Text messages can be used to deliver scams.

Vishing

Social Engineering

Phishing conducted through voice calls.

Example: A scam caller pretending to be technical support.

Why it matters: Attackers can use phone calls to create urgency.

Social Engineering

Social Engineering

Manipulating people into revealing information or performing actions.

Example: Pretending to be an employee to request access.

Why it matters: Security depends on people as well as technology.

Pretexting

Social Engineering

Creating a believable story or situation to obtain information or access.

Example: Someone pretending to be an employee needing account assistance.

Why it matters: False stories can manipulate trust.

Baiting

Social Engineering

Using an appealing offer or object to encourage someone to take an unsafe action.

Example: A suspicious free-download offer.

Why it matters: Curiosity can be used against users.

Brute Force Attack

Attacks

Trying many possible credentials or combinations until one works.

Example: Repeatedly testing possible passwords against a login system.

Why it matters: Strong passwords and rate limits can help reduce this risk.

DDoS

Attacks

Distributed Denial-of-Service; an attack that attempts to overwhelm a service with traffic.

Example: A website becomes unavailable because it receives massive amounts of unwanted traffic.

Why it matters: Availability can be disrupted.

DoS

Attacks

Denial-of-Service; an attempt to make a service unavailable to legitimate users.

Example: A service becomes overwhelmed by excessive requests.

Why it matters: It can affect system availability.

Zero-Day

Attacks

A vulnerability that is unknown or has not yet received an available fix at the time it is being exploited or discussed.

Example: Attackers exploit a newly discovered software flaw before a patch exists.

Why it matters: Defenders may have limited time to respond.

Exploit

Attacks

A technique or piece of code that takes advantage of a vulnerability.

Example: A security flaw is used to cause unintended behavior.

Why it matters: Exploits can turn weaknesses into real security incidents.

Credential Stuffing

Attacks

Using stolen username and password combinations against other services.

Example: Reusing leaked credentials from one website on another.

Why it matters: Password reuse increases account risk.

Man-in-the-Middle

Attacks

A situation where an attacker secretly interferes with communication between parties.

Example: An attacker intercepts network communication in an unsafe environment.

Why it matters: Secure protocols help protect communications.

Firewall

Defense

A security system that controls network traffic according to defined rules.

Example: Blocking unwanted inbound connections.

Why it matters: Firewalls can reduce unwanted network access.

Antivirus

Defense

Software designed to detect, prevent, or remove malicious software.

Example: Security software detecting a suspicious file.

Why it matters: Malware detection is an important defensive layer.

Endpoint Security

Defense

Protecting devices such as computers, phones, and servers.

Example: Security software installed on company laptops.

Why it matters: Endpoints are common targets.

Patch

Defense

A software update that fixes bugs, vulnerabilities, or other issues.

Example: Installing a security update for an operating system.

Why it matters: Patching can close known vulnerabilities.

Backup

Defense

A separate copy of important data kept for recovery.

Example: Keeping a protected copy of important files.

Why it matters: Backups can help recover from data loss or incidents.

Network Segmentation

Defense

Dividing a network into separate sections to control communication and limit exposure.

Example: Separating guest Wi-Fi from internal systems.

Why it matters: Segmentation can limit the spread of security incidents.

HTTP

Web Security

Hypertext Transfer Protocol, commonly used to transfer web resources.

Example: A browser requests a webpage using HTTP.

Why it matters: HTTP is fundamental to web communication.

HTTPS

Web Security

HTTP protected by TLS encryption.

Example: A secure website using https://.

Why it matters: HTTPS helps protect data in transit.

TLS

Web Security

Transport Layer Security, a protocol used to protect network communications.

Example: HTTPS commonly uses TLS.

Why it matters: TLS helps protect confidentiality and integrity during communication.

SQL Injection

Web Security

A vulnerability where untrusted input is improperly incorporated into database queries.

Example: Poorly designed input handling changes the intended database query.

Why it matters: Secure input handling helps protect databases.

XSS

Web Security

Cross-Site Scripting, a vulnerability involving untrusted content being executed in a user's browser.

Example: A vulnerable website displays unsafe user-controlled content.

Why it matters: XSS can affect users of vulnerable websites.

CSRF

Web Security

Cross-Site Request Forgery; a vulnerability where a user can be tricked into sending an unintended request.

Example: A malicious webpage attempts to trigger an action on another site.

Why it matters: Web applications need protections against unintended requests.

Cookie

Web Security

Small pieces of data stored by websites in a user's browser.

Example: A website uses a cookie to remember a session.

Why it matters: Cookies can affect authentication, privacy, and tracking.

Session

Web Security

A period of interaction between a user and a web application.

Example: Remaining logged into a website during a visit.

Why it matters: Secure session management protects accounts.

Cloud Computing

Cloud

Using computing resources such as servers and storage through network-accessible services.

Example: Storing files on a cloud platform.

Why it matters: Many modern systems rely on cloud infrastructure.

Cloud Security

Cloud

Practices used to protect cloud-based systems, applications, and data.

Example: Restricting access to cloud storage.

Why it matters: Cloud systems contain valuable information.

IaaS

Cloud

Infrastructure as a Service; cloud-based computing infrastructure such as virtual servers and storage.

Example: Renting virtual computing resources from a cloud provider.

Why it matters: IaaS is widely used to build online systems.

SaaS

Cloud

Software as a Service; software delivered over the internet.

Example: Using an online productivity application.

Why it matters: SaaS is common in modern organizations.

SOC

Security Operations

Security Operations Center; a team or facility responsible for monitoring and responding to security events.

Example: Analysts investigate suspicious login activity.

Why it matters: SOC teams help organizations detect threats.

SIEM

Security Operations

Security Information and Event Management; technology used to collect and analyze security-related logs and events.

Example: A SIEM collects logs from servers and security devices.

Why it matters: Centralized logs can help analysts investigate incidents.

Log

Security Operations

A record of activity generated by a system, application, or device.

Example: A login event recorded by a server.

Why it matters: Logs can provide evidence during investigations.

Alert

Security Operations

A notification indicating potentially suspicious or important activity.

Example: An alert for repeated failed login attempts.

Why it matters: Alerts help security teams notice potential threats.

Threat Intelligence

Security Operations

Information about threats, threat actors, tactics, techniques, and indicators.

Example: Information about a known malicious domain.

Why it matters: Intelligence can help defenders prepare and respond.

IOC

Security Operations

Indicator of Compromise; evidence that may suggest a security incident has occurred.

Example: A known malicious file hash.

Why it matters: IOCs can help analysts identify suspicious activity.

Digital Forensics

Forensics

The process of examining digital evidence to understand events and activity.

Example: Investigating files and logs after a security incident.

Why it matters: Forensics can help determine what happened.

Digital Evidence

Forensics

Information stored or transmitted digitally that may be relevant to an investigation.

Example: System logs related to an incident.

Why it matters: Evidence can help investigators understand events.

File Metadata

Forensics

Information about a file, such as timestamps, size, or other attributes.

Example: A file's creation and modification times.

Why it matters: Metadata can provide useful investigative clues.

Chain of Custody

Forensics

Documentation showing how evidence was collected, handled, transferred, and stored.

Example: Recording who handled an evidence device and when.

Why it matters: Proper handling helps preserve evidence integrity.

Incident Response

Security Operations

The organized process of detecting, containing, investigating, and recovering from security incidents.

Example: A security team responds after discovering a compromised account.

Why it matters: Fast and organized response can reduce damage.

Containment

Security Operations

Actions taken to limit the spread or impact of a security incident.

Example: Isolating an affected device from a network.

Why it matters: Containment can prevent an incident from spreading further.

Recovery

Security Operations

Restoring systems and operations after a security incident.

Example: Restoring a clean backup after an incident.

Why it matters: Organizations need to safely return to normal operations.

Incident

Security Operations

An event that threatens or violates the security of information or systems.

Example: An unauthorized account access event.

Why it matters: Recognizing incidents enables a response.

Penetration Testing

Careers & Tools

Authorized security testing designed to identify weaknesses in systems.

Example: A company hires testers to evaluate its own systems.

Why it matters: Authorized testing can reveal weaknesses before attackers do.

Ethical Hacker

Careers & Tools

A cybersecurity professional who performs authorized security testing.

Example: Testing a company's website with permission.

Why it matters: Ethical hackers help organizations improve security.

Red Team

Careers & Tools

A security team that simulates adversary behavior during authorized testing.

Example: A team tests whether an organization can detect simulated attacks.

Why it matters: Red teams can test real-world defensive readiness.

Blue Team

Careers & Tools

A defensive security team responsible for protecting and monitoring systems.

Example: Analysts investigate suspicious activity.

Why it matters: Blue teams defend systems against threats.

Purple Team

Careers & Tools

An approach that combines lessons from offensive and defensive security teams.

Example: Red and blue teams work together to improve detection.

Why it matters: Collaboration can strengthen security.

CTF

Careers & Tools

Capture The Flag; a cybersecurity competition or practice environment involving challenges.

Example: Solving a fictional security challenge to find a flag.

Why it matters: CTFs can provide hands-on learning.

SIEM Analyst

Careers & Tools

A security professional who investigates events and alerts using security monitoring systems.

Example: Reviewing suspicious login alerts.

Why it matters: Analysts help detect and investigate threats.

SOC Analyst

Careers & Tools

A cybersecurity professional who monitors systems and investigates potential security incidents.

Example: Investigating an unusual login from an unexpected location.

Why it matters: SOC analysts are an important part of defensive cybersecurity.

Zero Trust

Fundamentals

A security approach that does not automatically trust users or devices and continuously verifies access.

Example: A device must prove its identity before accessing a sensitive resource.

Why it matters: Modern networks can contain many different users and devices.

Security Policy

Fundamentals

A set of rules and guidelines describing how an organization protects information and systems.

Example: A company policy requiring MFA.

Why it matters: Policies help establish consistent security practices.

Defense in Depth

Defense

Using multiple layers of security controls instead of relying on one defense.

Example: Passwords, MFA, firewalls, monitoring, and backups working together.

Why it matters: If one defense fails, another may still help.

Security Awareness

Defense

Training and education designed to help people recognize and avoid security threats.

Example: Teaching employees how to recognize phishing.

Why it matters: People are an important part of cybersecurity.

Risk Assessment

Security Operations

The process of identifying and evaluating security risks.

Example: Reviewing which systems contain the most sensitive data.

Why it matters: Organizations need to prioritize their security efforts.

Security Monitoring

Security Operations

Continuously watching systems and activity for signs of suspicious behavior.

Example: Monitoring authentication logs.

Why it matters: Monitoring can help detect problems sooner.

VPN

Networking

Virtual Private Network; technology that creates a protected connection between a device and a network service.

Example: Connecting securely to an organization's network from another location.

Why it matters: VPNs can help protect network traffic and provide remote access.

Bandwidth

Networking

The amount of data that can be transmitted over a network connection during a given period.

Example: A network connection with higher bandwidth can carry more data.

Why it matters: Network capacity affects performance.

API

Web Security

Application Programming Interface; a defined way for software systems to communicate.

Example: A website uses an API to request information from a server.

Why it matters: APIs are common parts of modern applications and need security controls.

Authentication Token

Web Security

Data used by a system to represent an authenticated user's access or session.

Example: A web application uses a session token after login.

Why it matters: Tokens must be protected because they can represent access.

AES

Cryptography

Advanced Encryption Standard, a widely used symmetric encryption algorithm.

Example: AES can be used to encrypt stored information.

Why it matters: Strong encryption helps protect sensitive data.

Cryptography

Cryptography

The study and use of techniques for protecting information through mathematical methods.

Example: Encryption and digital signatures.

Why it matters: Cryptography supports many modern security systems.

Botnet

Malware

A collection of compromised devices that can be controlled by an attacker.

Example: Infected devices being used as part of a coordinated campaign.

Why it matters: Botnets can operate at large scale.

Insider Threat

Attacks

A security threat originating from someone with legitimate access to an organization's resources.

Example: An employee misusing access to sensitive information.

Why it matters: Security must account for authorized access as well as outside threats.

Security Control

Fundamentals

A safeguard designed to reduce security risk.

Example: MFA, firewall rules, or security training.

Why it matters: Controls help protect systems and information.

Vulnerability Analyst

Careers & Tools

A cybersecurity professional who identifies, evaluates, and helps prioritize vulnerabilities.

Example: Reviewing vulnerability scan results.

Why it matters: Finding weaknesses helps organizations fix them.

Cybersecurity Engineer

Careers & Tools

A professional who designs, builds, and maintains security technologies and systems.

Example: Designing secure network architecture.

Why it matters: Engineers help build security into technology.

Incident Responder

Careers & Tools

A cybersecurity professional who helps investigate and respond to security incidents.

Example: Helping contain a compromised system.

Why it matters: Responders help organizations recover from attacks.
